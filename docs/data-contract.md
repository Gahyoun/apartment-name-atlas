# 입력 규격

## 웹앱 입력

웹앱은 `data/processed/complexes.jsonl`과 `dataset_meta.json`을 읽는다. `scripts/collect_public_data.py`가 실제 원자료에서 생성하며 단순 CLI 입력과는 별도 규격이다.

필수 필드는 `id`, `name`, `sido`, `sigungu`, `dong`, `dong_code`, `approval_year`, `lat`, `lon`, `source_url`, `is_demo:false`다. 좌표가 없으면 `lat/lon`은 `null`이다. `name_variants`에 공시가격·건축물대장·도로명주소의 이름을 보존하고 `name_basis`에 대표 이름의 출처를 기록한다. 주소·승인일·좌표 연결 근거도 각 행에 보존한다. 같은 이름의 다른 단지를 하나로 합치지 않는다.

법정동 코드는 PNU의 앞 10자리이며, 화면의 동 선택은 현재 선택한 시도·시군구 아래에서 작동한다. 행정동과 법정동은 같은 개념이 아니다. 이름의 지명 후보가 주소와 문자열로 일치했다는 표시도 그 표현의 의미나 지리적 범위가 확정되었다는 뜻은 아니다.

`backend/server.py`가 사전과 주소 문맥을 이용해 토큰을 만들고 그래프·목록·지도·GIS 비교 API에 동일한 필터를 적용한다. 지도와 GIS는 실제 좌표·거리가 확인된 표본만 사용한다. 상세 API는 `docs/api.md`를 참조한다.

## 단순 CLI 입력

현재 분석기는 UTF-8 JSONL을 읽는다. 한 줄은 **한 단지의 수집 시점 이름 1개**다. 동일 파일에서 `complex_id`가 중복되면 오류로 중단한다. 날짜가 다른 반복 수집과 명칭 이력은 별도 파일로 보관하고, 현재명 표본을 먼저 확정한다.

| 필드 | 형식 | 의미 |
|---|---|---|
| `complex_id` | 비어 있지 않은 문자열 | 자료원 접두사를 붙인 단지 식별자; 예: `source:original_id` |
| `name_raw` | 비어 있지 않은 문자열 | 출처에서 받은 원문 명칭 |
| `region` | 비어 있지 않은 문자열 | 통일된 시도명; 데모는 `예시지역` 허용 |
| `completion_year` | 정수 또는 `null` | 이 프로젝트에서는 사용승인연도를 우선 사용; 누락은 추정하지 않음 |
| `observed_at` | `YYYY-MM-DD` | 이 이름을 원자료에서 확인한 날짜; 명명일을 의미하지 않음 |
| `source_url` | HTTP(S) URL | 원자료 출처; 데모에 한해 `null` 가능 |
| `is_demo` | 불리언 | 실제 자료는 `false`, 예제·합성 자료는 `true` |

정확한 사용승인일, 준공일의 종류, 주소, 시군구 코드, 원자료 ID, 다운로드 시각, 원자료 수정일은 원본 및 수집 기록에 별도 보존한다. 준공연도와 사용승인연도를 섞어 쓸 경우에는 연도의 근거를 별도 필드로 추가하고 집계 대상을 다시 정의해야 한다.

실데이터는 `data/raw/`에 원본을 먼저 저장하고, 출처별 변환 후 `data/processed/`에 저장한다. 여러 출처를 결합할 때는 원본 ID의 교차 대응표를 만든다. 동 주소가 다르거나 이름이 비슷하다는 이유만으로 자동 병합하지 않는다.

`source_url`에는 인증키를 포함하지 않는다. 인증키와 인증 응답은 결과물에 기록하지 않는다. 환경변수 이름과 사용 여부만 별도 수집 코드에서 다룬다.

## 예제와 실제 자료의 분리

`data/examples/names.jsonl`의 이름과 메타데이터는 기능 확인용이다. 실제 존재나 해당 시기의 유행을 증명하지 않는다. 모든 `completion_year`는 `null`이므로 데모 실행에서는 준공 연대별 결과가 비어 있어야 한다.

데모가 포함된 입력은 기본적으로 거부한다. `--allow-demo`를 명시한 경우에만 실행하며, 실제 자료와 섞여 있어도 전체 출력을 데모로 표시한다. 실제 연구 결과를 만드는 명령에는 이 옵션을 사용하지 않는다.

## 명칭 이력 확장: 아직 미구현

추후 별도 이름 이력 테이블에 `complex_id`, `name_raw`, `valid_from`, `valid_to`, `recorded_at`, `date_basis`, `source_url`을 저장할 예정이다. `valid_from`은 실제 사용 시작일을 확인한 경우에만 채운다. 기관의 이력 등록일만 확인되면 `recorded_at`에 기록한다. 현재 분석기에 여러 이름 버전을 넣어 시대 변화라고 해석하지 않는다.
