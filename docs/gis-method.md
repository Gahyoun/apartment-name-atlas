# 이름과 실제 입지의 연관성

사용자가 제시한 ‘아파트 작명법’ 이미지는 분석 가설의 출발점이다. 그림의 대응표가 사실이라는 전제는 두지 않는다.

## 1차로 검증하는 질문

| 이름 토큰 | 비교 지형·시설 | 해석 범위 |
|---|---|---|
| 파크 | 지도에 기록된 공원 | 공원 부지까지의 직선거리 |
| 리버·레이크 | 수면·하천 | 강·호수·연못 수면 및 강 중심선; 강변만의 결과가 아님 |
| 포레 | 숲 | 지도에 기록된 산림·수림 부지; 산 정상 거리가 아님 |
| 메트로 | 지하철역·출입구 | 지도에 기록된 지하철 시설; 열차 이용시간이 아님 |
| 에듀 | 학교 | 지도에 기록된 학교 부지; 학군 배정·교육의 질이 아님 |

오션·마리나, 센트럴과 4차선 도로, 시티와 노후 건물, 더퍼스트와 ‘주변에 아무것도 없음’은 아직 측정하지 않는다. 각각 해안·항만, 도로 폭/차로 수, 주변 건축연도, 접근가능 시설 집합이라는 별도 정의와 자료가 필요하다.

## 좌표를 결합하는 방법

전국 이름 표본은 한국부동산원 자료를 사용한다. GIS 1차 표본은 서울시 공동주택 공개자료에서 좌표가 확인되고, 두 자료의 도로명주소가 각각 유일하며 법정동·사용승인일까지 일치하는 단지로 한정한다. 아파트 이름의 유사도만으로 좌표를 붙이지 않는다. 주소의 행정동 중심점이나 지오코딩 실패 시 임의 좌표를 대입하지 않는다.

전국의 이름 표본 수와 GIS의 좌표·거리 측정 표본 수를 화면에서 별도로 표시한다. 이는 전국 입지 분석 완료를 뜻하지 않는다. 서울에서도 엄격한 연결에 성공한 단지만 포함되므로 선택 편향을 고려해야 한다.

## 거리

지형은 [OpenStreetMap](https://www.openstreetmap.org/copyright)의 공개 데이터를 [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)로 한 번 추출해 캐시한다. 타일 이미지를 분석용으로 대량 다운로드하지 않는다. 서울권 한정 bbox는 남쪽 위도/서쪽 경도/북쪽 위도/동쪽 경도 순서로 `37.35,126.70,37.75,127.25`다. 실제 타임스탬프와 도형 수는 `data/processed/gis_meta.json`에 기록한다.

| 지형 | OSM 선택 태그 | 범위의 한계 |
|---|---|---|
| 공원 | `leisure=park` | 이름이 공원이라도 이 태그가 없으면 누락될 수 있음 |
| 수면·하천 | `natural=water`, 선형 `waterway=river` | 호수·연못 및 강 중심선 포함; `stream`만 붙은 개울은 제외 |
| 산림·수림 | `landuse=forest`, `natural=wood` | 산 정상·녹지 전체·산책로의 대리값이 아님 |
| 학교 | `amenity=school` | 배정 학군·교육의 질·대학 전체가 아님 |
| 지하철 | `railway=station`과 `station=subway`, 점형 `railway=subway_entrance` | 역 중심점과 출입구가 혼재; 일반 철도역 전체가 아님 |

위·경도를 EPSG:5179로 변환한 뒤, 단지 대표점에서 가장 가까운 기록된 도형까지 거리를 미터로 계산한다. 면 안에 있으면 0m이며 면 바깥이면 경계까지, 선은 선까지, 점은 점까지의 거리다. Multipolygon은 외곽 링과 내부 홀을 구분한다. 단지 출입구부터의 보행 경로, 단지 전체 외곽, 조망 가능성을 측정한 값이 아니다.

추출 범위 경계까지의 거리보다 멀리 있는 시설만 찾았다면 범위 밖에 더 가까운 시설이 있을 수 있으므로 그 측정치를 쓰지 않는다. 시설이나 좌표가 없을 때는 미측정으로 남긴다. OSM 자체가 불완전하므로 ‘지도에 없는 시설은 현실에도 없다’고 간주하지 않는다.

## 비교와 검정

선택한 토큰을 가진 단지와 가지지 않은 단지의 거리 중앙값, 정한 반경 이내 비율, 표본 수를 함께 제공한다. 분모는 각각 실제 거리를 측정한 단지다. 두 집단 각각 5개 미만이면 비교 검정을 제공하지 않는다.

비교 가능한 **같은 시군구 × 사용승인 10년대** 묶음 안에서만 이름표를 999번 섞는다. 각 묶음의 토큰 보유 단지 수는 유지한다. 검정 통계량은 묶음별 평균 거리 차이를 토큰 보유 단지 수로 가중한 평균이다. 관측 통계량보다 절댓값이 크거나 같은 무작위 통계량 수에 1을 더해 1,000으로 나눈 양측 p값을 표시한다. 난수 시드는 고정해 재현 가능하게 한다.

전체 표본의 중앙값 차이와 이 층화 평균 차이는 다른 통계량이다. 비교 가능한 묶음에 남은 포함·비포함 단지 수도 별도로 기록한다. 연도가 없거나 비교 집단이 없는 묶음은 검정에서 제외한다. p=0.001은 이 999회 검정의 최소 해상도다. 동네·사업단위 공간상관과 브랜드·단지규모 등 교란이 남아 있으며, 다중 토큰 탐색 보정은 하지 않았으므로 p값은 탐색용으로만 해석한다.

현재 이름과 현재 지형을 비교한 연관성이다. 시설이 명명 이전부터 있었는지, 건설사가 입지 때문에 그 이름을 선택했는지, 주민이 어떻게 받아들였는지는 이 분석만으로 알 수 없다.

## 브랜드 분절과 민감도

사전의 긴 표현을 먼저 보호한다. 예를 들어 `아이파크`의 `파크`, `포레나`·`휴포레`의 `포레`는 해당 브랜드 바깥의 독립 토큰으로 세지 않는다. 이는 브랜드가 자연 이미지를 전달하지 않는다는 판정이 아니라 측정 단위의 선택이다. `seed-1.1.0`은 브랜드 14개와 `리버티` 전체어 보호를 보완했다. 리버티의 premium 분류는 잠정이며, 강을 뜻하는 리버 토큰의 자동 오탐을 줄이기 위한 처리다. 근거와 잔여 후보는 `dictionaries/brands.supplement.json`에 보존한다.

보고서는 동일 자료를 보완 사전의 항목 포함/제외 상태에서 다시 분절해 전국과 GIS 표본의 토큰 수 변화를 제시한다. 결과표에 쓰이는 기본값은 보완된 사전이다. 현재 사전은 전국 브랜드 전수목록이 아니고, 짧은 부분문자열과 개별 단지명의 의미는 여전히 검수 대상이다.

파크에 대해서는 좌표·거리 측정이 있는 표본 중 한솔솔파크 4건·대주파크빌 2건·문영퀸즈파크 1건을 제외한 비교, 여기에 파크리오 1건까지 제외한 비교를 추가한다. 이들은 검수가 끝나지 않은 브랜드·고유명 경계 사례이며, 이번 민감도에서만 관측행을 표본에서 제거한다. 비포함 집단에 재배치하거나 확인된 브랜드로 확정하지 않는다. 제외된 단지고유번호와 이름은 `results/initial-findings.json`의 `park_sensitivity`에 기록한다.

이 경우 비포함 집단의 원래 거리 중앙값은 유지되지만, 포함 집단 구성·층별 가중치·비교 가능한 묶음이 변하므로 층화 평균 통계량과 p값은 다시 계산한다. 후보 선정은 데이터 검수 이후 이루어졌으며 사전등록된 독립 검정이 아니다. p값의 임계치 통과 여부만으로 결론을 선택하지 않고 거리 차이의 방향·크기와 함께 기술한다.

## 재현

```bash
python3 -m pip install -r requirements-gis.txt
python3 scripts/collect_gis_features.py --download
python3 scripts/collect_gis_features.py --measure
python3 scripts/build_report.py
```

공개 API 추출은 캐시가 있을 때 반복 호출하지 않는다. 웹 화면은 저장된 자료를 읽고, 필터 변경마다 외부 API를 호출하지 않는다.

보고서 생성은 추가 네트워크 수집 없이 저장된 자료를 사용한다. `results/initial-findings.json`에 사전 버전·OSM 스냅샷 시각·입력 파일 SHA-256·검정 시드와 검정 표본 수를 기록한다. 결과를 해석할 때 사용승인연도를 이름이 생긴 연도로 바꾸어 읽지 않는다. 현재 명칭은 나중에 바뀌었을 수 있으며, 현존 자료 수록 단지의 비교에는 철거·개명·수록 여부에 따른 선택이 포함된다.
